# Apple 健康自動同步設定

運動後不用做任何事：iPhone 每晚自動把當天的 Apple Watch 運動送到雲端，下次打開 App 就會出現，並自動打卡。

- 騎車（戶外）→ 有氧・公路車；騎車（室內、沒有距離）→ 室內台；跑步 → 跑步；其他（健行、步行…）→ 有氧・其他
- 傳統 / 功能性肌力訓練 → 掛在當天重訓，首頁顯示「⌚ 52m · 310 kcal · ♥128」
- 以運動開始時間辨識，同一筆送兩次不會重複

## 一、更新雲端腳本（只做一次）

1. 打開 `Personal_Telemetry_DB` 試算表 → 擴充功能 → Apps Script
2. 全選刪除，貼上新版 [`gas/Code.gs`](../gas/Code.gs)，儲存
3. **部署 → 管理部署作業** → 點鉛筆 → 版本選 **新版本** → 部署（網址不變）

## 二、建立捷徑「運動同步」

捷徑 App → 捷徑 → 右上 ＋。依序加入以下動作（括號內為英文介面名稱；名稱可能隨 iOS 版本略有不同，選最接近的即可）：

1. **尋找健康樣本**（Find Health Samples）
   - 類型：**體能訓練**（Workouts）
   - 加入篩選條件：**開始日期** 在 **過去 2 天** 內
2. **重複每個項目**（Repeat with Each），以下 3～10 都放在重複裡面
3. **取得健康樣本的詳細資訊** → 選 **類型**（Workout Type）
4. **取得健康樣本的詳細資訊** → **開始日期**，接著 **格式化日期** → 格式選 **ISO 8601**，勾選包含時間
5. **取得健康樣本的詳細資訊** → **結束日期**，接著 **格式化日期** → **ISO 8601**
6. **取得健康樣本的詳細資訊** → **距離**（Total Distance）
7. **取得健康樣本的詳細資訊** → **能量**（Total Energy Burned）
8. **尋找健康樣本** → 類型 **心率**，篩選：開始日期 **晚於** 第 4 步的「開始日期」、結束日期 **早於** 第 5 步的「結束日期」
9. **計算統計資料** → **平均值**（輸入：第 8 步結果）；再加一個 **計算統計資料** → **最大值**
10. **取得 URL 的內容**（Get Contents of URL）
    - URL：雲端同步用的網頁應用程式網址（與 App 設定頁相同）
    - 方法：**POST**；要求本文：**JSON**，欄位如下表

| 鍵 | 類型 | 值 |
|---|---|---|
| `token` | 文字 | App 設定頁的 Token |
| `action` | 文字 | `health_workout` |
| `type` | 文字 | 第 3 步「類型」 |
| `start` | 文字 | 第 4 步格式化後的日期 |
| `end` | 文字 | 第 5 步格式化後的日期 |
| `distance_km` | 數字 | 第 6 步「距離」 |
| `kcal` | 數字 | 第 7 步「能量」 |
| `avg_hr` | 數字 | 第 9 步平均值 |
| `max_hr` | 數字 | 第 9 步最大值 |

數字欄位帶單位或千分位（例如「45.3 公里」「1,012」）也沒關係，雲端會自動解析。沒有的值（例如室內台沒有距離）留空即可。

先手動按 ▶︎ 執行一次。想看結果可以在第 10 步後面加 **顯示結果**，成功會看到 `"status":"IMPORTED"`（重送則是 `DUPLICATE`），確認沒問題後再刪掉這一步。

## 三、設成每天自動執行

捷徑 App → **自動化** → ＋ → **特定時間** → 23:30、**每天** → **立即執行**（關閉「執行時通知」）→ 選「運動同步」。

## 常見錯誤

| 回應 | 原因 |
|---|---|
| `UNAUTHORIZED` | Token 打錯 |
| `BAD_START` | 第 4 步沒有選 ISO 8601 格式 |
| `NO_HABIT` | App 還沒同步過新版的有氧項目：先打開 App 一次再重試 |
| 回應是一段 HTML | 網址不是 `…/exec` 結尾的網頁應用程式網址 |
